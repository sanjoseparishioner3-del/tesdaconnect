# Security, Privacy & Data Integrity Risk Assessment — TCTESDAConnect

**Classification Basis:** Directly verified inspection of middleware, Fortify/Auth actions, routes, controllers, Livewire components, database migrations/seeders, and offline PWA client scripts.

## 1. Risk Register (Ranked by Severity)

### CRITICAL Risks

| ID | Finding & Location | Impact | Target Modernization Control |
| :--- | :--- | :--- | :--- |
| **SEC-C1** | **`Referer` Header Bypass in `EnsureActiveAccount`** (`app/Http/Middleware/EnsureActiveAccount.php:21-24`) | Requests carrying a spoofed `Referer: https://<host>/settings/security` header bypass both `force_password_change` and `password_expires_at` enforcement across protected routes. | Enforce password-change/expiration state strictly via server-side JWT/session claims & RLS `is_password_current()` predicates — never trust HTTP `Referer`. |
| **SEC-C2** | **Unencrypted PII & Shared-Device Offline Persistence** (`public/offline-app.js`, `/login`, `offline.html`) | Default opt-in offline checkbox on `/login`, unauthenticated local account listing on `/login` and `/offline.html`, unencrypted IndexedDB PII (`snapshots` holding up to 100 learners' names, emails, contacts, scholar IDs), `localStorage` session trust letting locked/deactivated users view cached PII until next online sync, unkeyed `LAST_SYNC_KEY` across user switches, and **logout failing to purge IndexedDB/outbox data**. | Default offline caching **off** on shared terminals; require explicit user opt-in with short device TTL; purge all PII IndexedDB stores (`Dexie.delete()` / clear) on explicit logout or user switch; never trust client `localStorage` identity for deactivated accounts. |
| **SEC-C3** | **Downgraded Offline Password Verifier + Unthrottled Endpoint** (`routes/offline-sync.php`, `public/offline-app.js`) | `POST /offline-sync/verify-password` has no rate limiter; offline verifier uses WebCrypto PBKDF2-HMAC-SHA256 (`100,000` iterations) on HTTPS/localhost, but **silently downgrades to `4,000`-iteration pure-JS SHA-256 on plain HTTP** LAN deployments. | Eliminate client-stored password verifiers completely in Phase 4 target architecture; rely on active short-lived Supabase session tokens under TLS (`https://` enforced on Cloudflare Pages) + PIN/session-lock options without persisting passwords or weak digests. |
| **SEC-C4** | **Fortify `/login` & `/passkeys/login` Missing Account Status Gate; Admin Password Hygiene** (`config/fortify.php`, `ResetUserPassword`, `system/accounts`) | Passkey & login pipelines lack pre-session `active` rejection until `EnsureActiveAccount` runs; `ResetUserPassword` fails to clear `force_password_change`; `system/accounts` creates/updates accounts without `Password::default()` complexity or invalidating active sessions (`sessions` table). | Supabase Auth handles login/MFA/WebAuthn + `banned_until` deactivation invalidating refresh tokens; DB `profiles.account_status` + Edge Function `admin-revoke-sessions` revokes active JWT sessions immediately on deactivation. |

## 2. Philippine Data Privacy Act (RA 10173) & Sensitive Data Boundaries

The system stores sensitive personal information (SPI) and regulated trainee records requiring strict minimization, access segregation, and auditability:

- **Sensitive Tables & Fields:** `learner_profiles` (full name, home/birthplace address, `birthdate`, `sex`, `civil_status`, `uli_number`, `classifications`, `disability_types`, `disability_cause`, guardian details, `privacy_consent`), `learner_documents` (birth certificates, academic transcripts, valid IDs, barangay clearances), `enrollment_applications` (`scholar_id`, contact details), and `attendance_records`/`competency_progress`.
- **Mandatory Modernization Rules:**
  1. **Least-Privilege RLS:** Applicants/scholars may read/update **only** their own draft profile/documents (`learner_user_id = auth.uid()`), locked once submitted/verified unless explicitly returned by Registrar. Staff access (`registrar`, `focal_person`, `trainer`) must be scoped by `institution_user` membership (and batch assignment if `trainer` role is introduced), except designated `administrator` oversight roles.
  2. **Self-Role Escalation Prevention:** Block `UPDATE` on `profiles.role` / `user_roles` via RLS and `BEFORE UPDATE` trigger for all non-service-role callers (`current_setting('request.jwt.claim.role')` / admin Edge Function only).
  3. **Authoritative Duplicate Detection Without Auto-Merge:** When syncing or submitting trainee applications, server RPC checks `(normalized last_name, first_name, birthdate)` and `uli_number`/`email` matches across non-archived records and flags potential duplicates for human Registrar verification — **never silently merging or overwriting two learner identities**.
  4. **Minimal Offline Caching Policy:** Cache only minimum authorized operational payloads needed for offline read/draft work (e.g., active announcements, user's assigned training schedules, and user-initiated local intake drafts). Never sync private documents or institutional bulk rosters to unprivileged or shared browser caches, and surface clear online/offline timestamps plus stale-cache warnings on every offline view or report.
  5. **Immutable Audit Trail:** Log role assignments, account status changes, password/MFA resets, ULI assignments, enrollment confirmations/returns, record edits, certificate issuances, and offline conflict resolutions in append-only `security_audit_logs` with actor, institution, timestamp, and changed-field diffs.
